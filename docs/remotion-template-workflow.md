# Готовые анимации для нашей моушн-серии

Проверено 27 октября 2026. Этап: исследование источников и подготовка процесса. Текущий ролик не меняем. Шаблоны ещё не импортированы в производство и не получили художественный апрув.

## Зачем используем

Готовые компоненты должны экономить повторное написание счётчиков, масок, построения графиков, сообщений, переходов и фоновых движений. Из них берём механику и доступные настройки, затем приводим к постановке конкретного ролика. Ожидаемая экономия пока не измерена; обещаний в процентах или минутах нет.

Сюжетная причинность, взаимодействия предметов, хват руки, вес и контакт, география сцены и синхронизация с речью остаются режиссёрской работой. Для каждого фрагмента сначала записываем, что изменилось и почему. Затем выбираем готовый приём, который показывает это изменение.

## Что показало чтение трёх компонентов RenderComp

- **TextMaskReveal:** полезная механика маски и последовательного раскрытия строк. Тайминги привязаны к константам кадров. Условие показа цветной маски выглядит несовместимым с описанным выходом блока: его нужно проверить в движении перед адаптацией. Длинные русские строки отдельно измерять по ширине.
- **KpiCounter:** барабанные цифры, фиксированный формат итогового числа, отдельные единицы. Есть раскладка для широкого и вертикального кадра. Перед применением заменить англоязычные сокращения и карточную оболочку, если они не подходят сцене. Отрицательные значения не поддерживаются текущей логикой счётчика без изменения кода.
- **PixelMosaicTransition:** собственный процедурный рисунок дня и ночи, внутреннее поле 480×270, зависимость от `src/pixel-kit`. Компонент не принимает две произвольные сцены. При размере ячейки 1 цикл способен создать 129 600 SVG-прямоугольников за кадр, плюс дополнительные эффекты. Нужны адаптация источника изображения, вертикальной геометрии и проверка нагрузки. Не ставить по умолчанию на каждый стык.

Эти выводы получены из кода. Превью в этом исследовании не рендерились и не оценивались как готовое движение.

## Навыки

Проверять доступность в текущем окружении; полезны: `remotion-best-practices`, `remotion-markup`, `remotion-render`, `remotion-captions`, `remotion-studio`; для постановки используется `motion-story-director`.

Дополнительные официальные навыки, изученные в исходном исследовании:

- `remotion-create`: создание композиции и корректное подключение к существующему проекту.
- `remotion-docs`: поиск актуальных официальных инструкций.
- `remotion-interactivity`: доступные для редактирования элементы, параметры и сцены в Studio.

Исходное исследование использовало навыки версии 4.0.539 из [remotion-dev/skills](https://github.com/remotion-dev/skills), ревизия 30d4553ecd46fbc5212fd0ff006ae43af522158b. Это не подтверждает их установку на машине получателя. Версию пакетов текущего проекта проверять отдельно; не обновлять её автоматически ради навыка.

Сторонний [SKILL.md ali-abassi](https://github.com/ali-abassi/remotion-templates/blob/main/SKILL.md) изучен, но не подключён как рабочая инструкция. В примерах есть `Math.random()` при рендере и при создании частиц: результат может различаться между запусками и экземплярами рендера. Есть рекомендации цветного выделения слов и общие стилевые правила, которые расходятся с принятыми правилами нашей серии. Для API и структуры кода используем официальные навыки; каталог механик рассматриваем отдельно.

## Короткий рабочий порядок

1. По принятой озвучке определить действие фрагмента и его результат. Например: число уменьшается, документ раскрывается, сигнал доходит до прибора, путь встречает преграду.
2. Посмотреть [локальный каталог кандидатов](remotion-template-catalog.json). Отобрать максимум три подходящих варианта для конкретного вопроса. Не загружать весь банк перед каждым выпуском.
3. Проверить движение выбранного превью без слышимого звука, затем исходник, зависимости и условия переноса. Статусы «прочитан код», «просмотрено движение» и «принят в нашем стиле» фиксировать отдельно.
4. Перенести минимальный компонент. Записать URL, ревизию, исходный путь, уведомление об авторстве и изменения. Для пиксельных шаблонов учитывать общие helper-модули. Не запускать неизвестный пакет из команды в посте без проверки его источника.
5. Адаптировать к 1080×1920, 30 fps и длительности реплики. Проверить русские строки, естественные единицы, точные значения, итоговое состояние и время чтения. Извлечь вход, смысловое действие и выход; не обрезать середину эффекта ради тайминга.
6. Привести цвета, шрифты, толщины линий, свет и амплитуду движения к общему паспорту ролика. Фон и карточная оболочка из демо не обязаны переноситься вместе с механикой.
7. Сохранить редактируемые текст, значения, цвета и параметры движения. Использовать кадровую анимацию и воспроизводимую случайность. Все `remotion` и `@remotion/*` в конкретном проекте держать на одной совместимой версии.
8. Сделать одну короткую пробу 3–8 секунд с настоящим русским текстом и субтитрами. Проверить стык, края, нагрузку и связь с озвучкой. Затем продолжать по [действующему моушн-регламенту](motion-production-playbook.md), без дополнительных кругов проверки неизменившегося материала.
9. В манифесте ролика сохранить одну короткую запись: источник, выбранная механика, статус адаптации и результат пробы. Удачный адаптированный компонент включить в нашу библиотеку для повторного использования.

## Правила нашей серии сохраняются

Полноэкранная графика и динамические фоны; фотографии и сгенерированные растровые сцены не используем. Одноцветные дословные субтитры снизу синхронизируются с озвучкой. Не превращаем нижнюю область в повторяющийся таймлайн. Тире в тексте озвучки запрещены. Красивый вход не заменяет развитие сцены после него. Музыка, голос и уже принятые субтитры сохраняются при визуальной адаптации, если нет отдельной причины менять их.

Первый набор для обсуждения: раскрытие текста маской, числовой счётчик, построение графика, круговая смена масштаба, сравнение двух состояний, последовательные сообщения. Пиксельный переход добавить отдельным экспериментом под подходящую тему.

## Где хранить результаты дальнейшего отбора

Каталог содержит ссылки и статусы исследования исходников. Переносимая поставка не включает сторонний код, превью и личные рабочие адаптации. Пробы вести отдельно от закрытых роликов, например в work/remotion-template-lab/. Принятые адаптации хранить с параметрами, коротким превью, исходной лицензией и карточкой применения. Информационная работа с библиотекой сама по себе не разрешает менять или рендерить текущий ролик.
